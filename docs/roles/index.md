# Роли в команде

## Теория: структура IT-команды в стартапе

В стартапе из 10 человек каждая роль критична. В отличие от крупных компаний, где обязанности размазаны по десяткам людей, у нас **высокая степень ответственности** и **разнообразие задач**. Каждый член команды влияет на продукт напрямую.

### Принципы организации

- **Flat structure** — минимум бюрократии, максимум автономии
- **T-shaped специалисты** — глубокая экспертиза в одной области + базовое понимание смежных
- **Full ownership** — ты отвечаешь за фичу от идеи до production
- **Cross-functional collaboration** — разработчики, QA и дизайнеры работают вместе, а не по очереди

### Модель взаимодействия

```
Product Idea
     ↓
Designer → создаёт UI/UX
     ↓
Tech Lead → декомпозирует, оценивает
     ↓
Developers → пишут код + unit tests
     ↓
QA → тестирует, ищет edge cases
     ↓
DevOps → деплоит, мониторит
     ↓
Users получают фичу
```

На каждом этапе возможны итерации назад. Код возвращается из review, дизайн дорабатывается после тестирования, деплой откатывается при проблемах.

## Описание ролей

### Tech Lead (TL)

**Кто это:** Технический лидер команды. Мост между бизнесом, продуктом и разработкой.

**Ответственность:**
- Архитектурные решения и technology stack
- Code review и качество кода
- Менторинг разработчиков
- Планирование спринтов и декомпозиция задач
- Разрешение технических блокеров
- Коммуникация с stakeholders
- Onboarding новых разработчиков

**Что делает на практике:**
- Проводит 1:1 с командой разработки
- Review-ит сложные PR
- Пишет ADR (Architecture Decision Records)
- Решает, какую библиотеку внедрять
- Выступает техническим экспертом на встречах

**С кем работает:**
- Product Manager / Founder — по приоритетам и срокам
- DevOps — по инфраструктуре
- Все разработчики — по задачам и review

---

### Developer (Software Engineer)

**Кто это:** Разработчик, который создаёт продукт.

**Ответственность:**
- Реализация фич от идеи до production
- Написание чистого, поддерживаемого кода
- Unit tests и интеграционные тесты
- Code review коллег
- Участие в обсуждении архитектуры
- Документирование своих решений

**Что делает на практике:**
- Пишет код по тикетам из backlog
- Создаёт PR и проходит code review
- Фиксит баги
- Рефакторит legacy-код
- Участвует в daily standup и planning

**Ключевые навыки:**
- Владение основным языком (Python / JavaScript / Go / и т.д.)
- Понимание Git и Git workflow
- Умение писать тесты
- Базовое понимание DevOps (Docker, CI/CD)

**С кем работает:**
- Tech Lead — по архитектуре и сложным задачам
- QA — при фиксе багов и уточнении поведения
- Designer — при вёрстке UI

---

### QA Engineer (Quality Assurance)

**Кто это:** Инженер по качеству, который гарантирует, что продукт работает как задумано.

**Ответственность:**
- Тестирование нового функционала
- Регрессионное тестирование перед релизами
- Составление тест-кейсов и чек-листов
- Автоматизация тестирования (E2E, API tests)
- Заведение баг-репортов и контроль их исправления
- Участие в обсуждении требований до начала разработки

**Что делает на практике:**
- Проверяет фичи по acceptance criteria
- Пишет автоматизированные тесты
- Заводит баги с чёткими steps to reproduce
- Проводит exploratory testing
- Анализирует метрики качества

**Ключевые навыки:**
- Аналитическое мышление и внимание к деталям
- Понимание тестовых пирамид
- Опыт с тестовыми фреймворками
- Умение писать чёткие баг-репорты

**С кем работает:**
- Разработчики — при reproduced багах и уточнении поведения
- Tech Lead — при планировании тестовой стратегии
- DevOps — при настройке CI/CD для тестов

---

### DevOps Engineer

**Кто это:** Инженер, который строит и поддерживает инфраструктуру разработки.

**Ответственность:**
- CI/CD pipelines и автоматизация деплоев
- Управление облачной инфраструктурой (AWS / GCP / Azure)
- Мониторинг, alerting и observability
- Безопасность и access management
- Управление окружениями (dev, staging, production)
- Database administration (backup, миграции)
- Оптимизация затрат на инфраструктуру

**Что делает на практике:**
- Настраивает GitHub Actions / Jenkins / GitLab CI
- Поднимает сервера и управляет Kubernetes
- Настраивает Prometheus / Grafana / Datadog
- Реагирует на инциденты инфраструктурного характера
- Автоматизирует рутинные операции

**Ключевые навыки:**
- Облачные платформы (AWS / GCP / Azure)
- Containerization (Docker, Kubernetes)
- Infrastructure as Code (Terraform, Ansible)
- Скриптинг (Bash, Python)
- Security best practices

**С кем работает:**
- Tech Lead — при архитектурных решениях, затрагивающих инфраструктуру
- Разработчики — при настройке dev-окружений
- QA — при поднятии тестовых стендов

---

### UX/UI Designer

**Кто это:** Дизайнер, который проектирует пользовательский опыт и интерфейс.

**Ответственность:**
- Проектирование пользовательских сценариев (UX)
- Создание визуального дизайна интерфейсов (UI)
- Поддержание Design System
- Проведение user research и usability-тестирования
- Подготовка макетов для development handoff
- Контроль соответствия реализации дизайну

**Что делает на практике:**
- Создаёт wireframes и прототипы в Figma
- Проводит интервью с пользователями
- Дизайнит новые экраны и флоу
- Поддерживает библиотеку компонентов
- Делает design review готовых фич

**Ключевые навыки:**
- Figma (основной инструмент)
- Понимание принципов usability и accessibility
- Навыки прототипирования
- Базовое понимание frontend-разработки
- Коммуникация и презентация решений

**С кем работает:**
- Product Manager / Founder — по продуктовым требованиям
- Разработчики — при handoff и review реализации
- QA — при тестировании UI

## Распределение ролей в нашей команде

| Роль | Количество |
|------|------------|
| Tech Lead | 1 |
| Developer | 4 |
| QA Engineer | 3 |
| DevOps Engineer | 1 |
| UX/UI Designer | 1 |
| **Итого** | **10** |

**Соотношение разработка / QA:** 4:3 — плотное покрытие тестированием, что критично для стартапа, где качество напрямую влияет на retention пользователей.

**DevOps:** 1 на 9 инженеров — стандартное соотношение для команды такого размера. При росте до 15+ человек стоит подумать о втором DevOps.

**Designer:** 1 на всю команду — при росте до 20+ человек или при запуске второго продукта потребуется расширение.
